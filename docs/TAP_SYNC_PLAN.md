# ແຕະໃຫ້ຕົງ (Tap Sync) — ແຜນພັດທະນາ

> ສ້າງ: 2026-10-09 · ສະຖານະ: **ແຜນ** · ກ່ຽວຂ້ອງ: [PRO_EDITOR_PLAN.md](PRO_EDITOR_PLAN.md) (ໄລຍະ T)
> ໄອເດຍຈາກເຈົ້າຂອງແອັບ: ຟັງສຽງ ແລ້ວແຕະທີລະປະໂຫຍກ ບອກວ່າຄຳນີ້ເວົ້າຮອດໃສ → ແຕະຕໍ່ໄປ → ຊັບຕົງກັບສຽງທຸກປະໂຫຍກ

---

## 1. ເປັນຫຍັງຈຶ່ງຄຸ້ມ

- **AI ຈັບເວລາພາສາລາວຍັງບໍ່ແມ່ນຍຳ:** ມັກໄວ ຫຼື ຊ້າໄປ 0.3–1 ວິ. ການລາກແກ້ທີລະອັນເທິງ timeline ຊ້າ ແລະ ເມື່ອຍ.
- **ການແຕະຕາມສຽງໄວກວ່າ:** ຄລິບ 1 ນາທີ (~15 ປະໂຫຍກ) ຄວນແລ້ວໃນ ~2 ນາທີ.
- **ໃຊ້ໄດ້ໂດຍບໍ່ຕ້ອງມີ AI:** ຜູ້ໃຊ້ວາງບົດເອງ (ເນື້ອເພງ, script) ແລ້ວແຕະ. ບໍ່ຕ້ອງໃຊ້ API key ແລະ ບໍ່ມີຄ່າໃຊ້ຈ່າຍ.
- **ເປີດຕະຫຼາດໃໝ່:** ເພງລາວແບບ karaoke (ໂໝດແຕະທີລະຄຳ).
- **ແນວຄິດທີ່ພິສູດແລ້ວ:** ໂປຣແກຣມເຮັດຊັບ ແລະ karaoke ຫຼາຍໂຕມີການຈັບເວລາດ້ວຍການແຕະ. KarnSub ຈະເປັນໂຕທຳອິດທີ່ອອກແບບມາສຳລັບພາສາລາວໃນມືຖື.
- **ບໍ່ຕ້ອງລໍຖ້າການຂຽນ editor ໃໝ່:** ໃຊ້ `SubtitleSegment.startTime/endTime/wordTimings` ທີ່ມີຢູ່ແລ້ວ. ບໍ່ຕ້ອງປ່ຽນ model, ສະນັ້ນ **ອອກໄດ້ກ່ອນ 5 ໄລຍະ**.

## 2. ຂັ້ນຕອນການໃຊ້ (User flow)

```
Editor → ຊັບ → [ແຕະໃຫ້ຕົງ]
   ① ເລືອກຂໍ້ຄວາມ:  ຊັບທີ່ AI ສ້າງແລ້ວ  |  ວາງບົດເອງ (ແບ່ງແຖວອັດຕະໂນມັດ)
   ② ຕັ້ງຄ່າໄວ:      ຄວາມໄວ 0.5× / 0.75× / 1×  ·  ໂໝດ ກົດຄ້າງ / ແຕະ  ·  ດູດເຂົ້າສຽງ ✓
   ③ ບັນທຶກ:        ສຽງຫຼິ້ນ → ກົດ/ແຕະຕາມປະໂຫຍກ → ຈົບອັດຕະໂນມັດເມື່ອຄົບ
   ④ ກວດ + ປັບລະອຽດ: ຫຼິ້ນຄືນພ້ອມຊັບ, ປັບ ±50 ms
   ⑤ ບັນທຶກ → ກັບ editor (undo ໄດ້ 1 ຂັ້ນ)
```

### ໜ້າຈໍບັນທຶກ (③)
- **ເທິງ:** preview ວິດີໂອ (ນ້ອຍ) + waveform ເລື່ອນຜ່ານ playhead ກາງຈໍ ພ້ອມຂີດເວລາທີ່ແຕະແລ້ວ.
- **ກາງ:** ປະໂຫຍກປັດຈຸບັນ **ໂຕໃຫຍ່**, ປະໂຫຍກຕໍ່ໄປ ໂຕຈາງໃຕ້ມັນ, ແລະ ຕົວນັບ "7 / 15".
- **ລຸ່ມ:** **ປຸ່ມໃຫຍ່ເຄິ່ງຈໍ**, ໃຊ້ໂປ້ມືກົດໄດ້ສະດວກ.
  - **ໂໝດກົດຄ້າງ** (ແນະນຳ): ກົດ = ເລີ່ມເວົ້າ, ປ່ອຍ = ເວົ້າຈົບ. ຮັບມືຊ່ວງງຽບລະຫວ່າງປະໂຫຍກໄດ້ຖືກຕ້ອງ.
  - **ໂໝດແຕະ:** ແຕະ = ຈົບປະໂຫຍກນີ້ ແລະ ເລີ່ມປະໂຫຍກຕໍ່ໄປທັນທີ. ເໝາະກັບການເວົ້າຕໍ່ເນື່ອງ ແລະ ເພງ.
- **ປຸ່ມຂ້າງ:**
  - **↶ ກັບ 1 ປະໂຫຍກ:** ລຶບເວລາຂອງປະໂຫຍກກ່ອນ ແລ້ວຫຼິ້ນຄືນກ່ອນ 2 ວິ.
  - **⏸ ຢຸດ** ແລະ **ຂ້າມ** (ເກັບເວລາເກົ່າໄວ້).
- **ປຸ່ມ volume ຂອງມືຖື = ປຸ່ມກົດ:** ແມ່ນຍຳກວ່າການແຕະຈໍ ແລະ ບໍ່ຕ້ອງເບິ່ງຈໍ. ເປີດສະເພາະຕອນຢູ່ໜ້ານີ້.
- **ສັ່ນເບົາໆ** ທຸກຄັ້ງທີ່ກົດ.

## 3. ຕົວຊ່ວຍໃຫ້ "ເປະ" (ຫົວໃຈຂອງຟີເຈີ)

| ຕົວຊ່ວຍ | ເຮັດຫຍັງ |
|---|---|
| **ຊົດເຊີຍການຕອບສະໜອງ** | ຄົນເຮົາກົດຊ້າກວ່າສຽງ ~150–250 ms. ຄ່າເລີ່ມຕົ້ນ −180 ms. ມີ **ປັບຕາມມື** 10 ວິ: ແຕະຕາມສຽງບີບ 8 ຄັ້ງ → ຄ່າສະເລ່ຍ. ເກັບໄວ້ໃນເຄື່ອງ |
| **ຫູຟັງ Bluetooth** | BT ດີເລ 100–300 ms ⚠️. ກວດ audio route; ຖ້າເປັນ BT ໃຫ້ເຕືອນ + ໃຫ້ປັບຕາມມືອີກຄັ້ງ |
| **ດູດເຂົ້າສຽງ (snap)** | ຫຼັງກົດ, ຊອກຈຸດເລີ່ມສຽງ (onset) ຫຼື ຈຸດທີ່ສຽງຫາຍໃກ້ສຸດ ±300 ms ຈາກ `detectSpeechOnsets` / `detectSpeechRegions` (ມີແລ້ວໃນ `MainActivity.kt`) ແລ້ວຍ້າຍໄປຕົງນັ້ນ. ສະແດງຈຸດເດີມ ແລະ ຈຸດທີ່ດູດ ເທິງ waveform |
| **ຄວາມໄວຊ້າລົງ** | 0.5× / 0.75× (`video_player` `setPlaybackSpeed`); ເວລາທີ່ບັນທຶກຄິດໄລ່ກັບເປັນ 1× ອັດຕະໂນມັດ |
| **ກົດລະບຽບກັນຜິດ** | ຈົບ ≥ ເລີ່ມ + 300 ms; ບໍ່ໃຫ້ຊ້ອນປະໂຫຍກກ່ອນ; ຊັບສະແດງຢ່າງໜ້ອຍ 0.7 ວິ; ເຕືອນເມື່ອຕົວອັກສອນ/ວິ ໄວເກີນອ່ານທັນ |

## 4. ວາງບົດເອງ → ແບ່ງແຖວອັດຕະໂນມັດ

- ແບ່ງຕາມ: ແຖວໃໝ່ → ເຄື່ອງໝາຍ (`.` `?` `!` `ໆ` ຍະຫວ່າງຍາວ) → ຄວາມຍາວສູງສຸດ (ຕັ້ງໄດ້, ຄ່າເລີ່ມຕົ້ນ 28 ຕົວອັກສອນ)
- **ບໍ່ຕັດກາງຄຳລາວ:** ໃຊ້ `lao_word_service.dart` (`segmentWords`) ເພື່ອຫາຈຸດຕັດຄຳ
- ໜ້າກວດກ່ອນເລີ່ມ: ລາກລວມ ຫຼື ແຍກແຖວໄດ້

## 5. ໂໝດແຕະທີລະຄຳ (Karaoke) — ຂັ້ນທີ 2

- ແຕະຕາມແຕ່ລະຄຳ (ຕັດຄຳດ້ວຍ `segmentWords`) → ຂຽນລົງ `wordTimings` → ໃຊ້ກັບ karaoke highlight / Word Pop ທີ່ມີແລ້ວ
- ເຮັດໄດ້ທັງທີລະປະໂຫຍກ: ເລືອກປະໂຫຍກ → ແຕະຄຳໃນປະໂຫຍກນັ້ນ

## 6. ໂຄງສ້າງ code

| ໄຟລ໌ | ໜ້າທີ່ |
|---|---|
| `lib/services/tap_sync_session.dart` (ໃໝ່) | Logic ລ້ວນ (ບໍ່ມີ UI): ແຕະ → ເວລາ, ຊົດເຊີຍ, snap, undo, ກົດລະບຽບ. **ມີ unit test** |
| `lib/services/script_splitter.dart` (ໃໝ່) | ວາງບົດ → ແບ່ງແຖວ |
| `lib/screens/tap_sync_screen.dart` (ໃໝ່) | ໜ້າຈໍ ①–④. **ບໍ່ໃສ່ໃນ `editor_screen.dart`** (ມັນໃຫຍ່ພໍແລ້ວ) |
| `test/tap_sync_session_test.dart` (ໃໝ່) | ທົດສອບ offset, snap, undo, ກົດລະບຽບ, ຄວາມໄວ 0.5× |
| `MainActivity.kt` | ເພີ່ມ: ຈັບປຸ່ມ volume (`dispatchKeyEvent`) ສະເພາະຕອນເປີດໜ້ານີ້; ກວດ audio route BT |
| `lib/i18n/i18n.dart` | ຂໍ້ຄວາມ lo + th ທັງໝົດ |
| `editor_screen.dart` | ພຽງເພີ່ມປຸ່ມ "ແຕະໃຫ້ຕົງ" ໃນແຖບຊັບ + ຮັບຜົນກັບມາເປັນ 1 undo step |

ເມື່ອ model ໃໝ່ (ໄລຍະ 1) ມາຮອດ: `TapSyncSession` ບໍ່ຂຶ້ນກັບ UI → ຍ້າຍໄປໃຊ້ກັບ `SubtitleElement` ໄດ້ງ່າຍ.

## 7. ຂັ້ນຕອນ ແລະ ເວລາ (ຄາດຄະເນ)

| ຂັ້ນ | ວຽກ | ເວລາ |
|---|---|---|
| T1 | `TapSyncSession` + unit test | 3 ວັນ |
| T2 | ໜ້າບັນທຶກ: ກົດຄ້າງ/ແຕະ, ປະໂຫຍກໃຫຍ່, waveform, ↶, ສັ່ນ, ຄວາມໄວ | 4 ວັນ |
| T3 | ດູດເຂົ້າສຽງ + ປັບຕາມມື + ກວດ BT + ປຸ່ມ volume | 3 ວັນ |
| T4 | ໜ້າກວດ + ປັບລະອຽດ ±50 ms | 3 ວັນ |
| T5 | ວາງບົດເອງ + ແບ່ງແຖວ | 2 ວັນ |
| T6 | ໂໝດແຕະທີລະຄຳ (karaoke) | 3 ວັນ |

ລວມ **~3 ອາທິດ**. ອອກ **T1–T4 ເປັນ test APK ກ່ອນ** (v1.3.x), ແລ້ວ T5–T6 ຕາມມາ.

## 8. ວັດຜົນ

- ຄລິບ 1 ນາທີ (~15 ປະໂຫຍກ) ແລ້ວພາຍໃນ **≤ 2 ນາທີ** ລວມການກວດ
- ຄວາມຄາດເຄື່ອນ (median) **≤ 100 ms** ເມື່ອທຽບກັບເວລາທີ່ຈັບດ້ວຍມືຢ່າງລະອຽດ (ເປີດ snap)
- ທົດສອບກັບຜູ້ໃຊ້ລາວແທ້ 5 ຄົນ: ສຽງເວົ້າ 2 ຄລິບ + ເພງ 1 ຄລິບ; ຖາມວ່າງ່າຍກວ່າລາກເທິງ timeline ບໍ
